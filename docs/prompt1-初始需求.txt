请用 Python 3.13 编写一个带 GUI 的桌面工具，用于从 TXT 小说文件中查找并删除广告语句。界面使用 Tkinter（标准库），代码需完整可运行，并包含清晰注释。最终程序应能在 Windows 下直接双击运行，也可使用 PyInstaller 打包成单个 exe 文件。

## 0. 打包 exe 的特殊要求（用于后续分发）
- 程序确保使用标准库，避免第三方依赖，这样打包时无需处理隐藏导入。
- 如果打包为 exe，推荐使用 PyInstaller 命令：`pyinstaller --onefile --windowed --name 小说广告清理工具 your_script.py`。
- 打包时需注意：Tkinter 在 Windows 下作为标准库的一部分，PyInstaller 通常能自动检测，但部分系统可能需要手动指定 tcl/tk 路径。代码中不要引入动态加载或外部数据文件（如图标），保持单文件即可。
- 若需要在程序内部处理路径（如桌面路径），必须使用 `os.path.expanduser` 并考虑打包后运行路径的变化，避免使用 `__file__` 相对路径去读写临时文件（本工具不涉及）。

## 1. 界面要求
- 窗口标题：小说广告清理工具
- 布局简洁，从上到下依次为：
  1) 文件选择行：标签“文件：” + 只读 Entry（显示路径） + “浏览”按钮（打开文件选择对话框，过滤 *.txt）
  2) 检索词输入行：标签“检索词：” + 宽 Entry（用于输入表达式） + “检索”按钮
  3) 操作行：“删除广告”按钮 + “覆盖原文件”复选框（默认不勾选，表示另存为新文件 `原文件名_clean.txt`；勾选则直接覆盖原文件）
  4) 状态栏：一个 Label 或只读 Text（高度 2~3 行）用于显示操作进度和结果
- 窗口初始大小合适，控件自适应调整

## 2. 核心功能

### 2.1 选择文件
- 用户通过“浏览”按钮选择一个 .txt 文件（通常 10~20 MB）。文件路径显示在 Entry 中。
- 点击“检索”前，必须已选择文件并在检索词框输入非空内容，否则给出提示。

### 2.2 检索词输入与表达式解析
- 用户在输入框中输入检索词，支持用 ` AND ` 和 ` OR ` 组合多个词（注意：AND/OR 前后各有一个空格，且必须大写）。
- 每个词本身为连贯整体，不可拆分。
- 表达式解析逻辑：以 ` OR ` 为分隔符，将表达式拆分成多个“与组”；每组内再用 ` AND ` 拆分成多个词。一个句子只要满足**任意一个“与组”中的所有词都出现在句中**，即视为匹配。
  示例：`小说 AND 广告 OR 网址` 表示匹配同时包含“小说”和“广告”的句子，或包含“网址”的句子。
  示例：`广告 OR 无弹窗 AND 清爽` 匹配包含“广告”，或同时包含“无弹窗”和“清爽”的句子。
- 如果输入不含 ` AND ` 或 ` OR `，则视为单个检索词，句子包含该词即匹配。

### 2.3 检索逻辑
- 程序读取文件全部文本（十几 MB 可直接读入内存）。需处理编码问题：依次尝试 `utf-8-sig`、`gbk`、`gb18030` 打开文件。若均失败则弹出错误提示，并告知用户手动转换编码后再试。
- 句子边界定义为以下字符之一：`。！？!?\n`（包含中英文句号、问号、感叹号以及换行符）。
- 分割方法：使用正则 `re.split(r'(?<=[。！？!?\n])', text)` 将文本拆分成句子列表。每个元素**包含结尾的分隔符**（最后一个元素若没有分隔符则不含）。例如 `"第一句。广告句。第三句。"` 拆分为 `["第一句。", "广告句。", "第三句。"]`。
- 遍历每个句子，判断是否包含检索词（根据解析的表达式匹配）。如果是，则标记为待删除的广告句。匹配使用 `in` 操作符，区分大小写，且包含即可（无需全词匹配）。

### 2.4 检索结果输出
- 点击“检索”按钮后，程序执行检索，不在界面展示内容，而是在用户**桌面**生成 `检索结果.txt` 文件。
- 桌面路径获取方式：`os.path.join(os.path.expanduser('~'), 'Desktop')`，若该目录不存在，则回退到 `os.path.expanduser('~')`。
- 文件内容：每行一条匹配的广告句，格式为 `[序号] 句子内容`（序号从1开始）。最后一行可附加总计信息，如“共找到 N 条广告句”。写入编码为 UTF-8（带 BOM `utf-8-sig`），确保在 Windows 记事本中正常显示中文。
- 状态栏更新为“检索完成，共找到 N 个广告句，结果已保存至桌面检索结果.txt”。

### 2.5 删除功能
- 用户确认 `检索结果.txt` 无误后，点击“删除广告”按钮。
- 点击后，必须弹出确认对话框，显示“即将删除 N 句广告，是否继续？”，用户确认后才能执行删除。
- 删除规则：从原文本中移除所有被标记为广告句的整个句子元素（包括该句子末尾的分隔符），但不删除它前面的分隔符。由于分割时保留分隔符在末尾，因此只需丢弃匹配的句子元素，其余元素直接拼接。示例：
  - 原文：`第一句。广告网址。第三句。` → 删除后：`第一句。第三句。`
  - 原文：`开头广告！第二句？` → 删除后：`第二句？`
  - 原文：`第一行\n广告行\n第三行` → 删除后：`第一行\n第三行`
- 文件保存策略：
  - 若“覆盖原文件”复选框未勾选（默认），则将清理后的内容写入**原文件所在目录**，文件名为 `原文件名_clean.txt`。原文件不做修改。
  - 若“覆盖原文件”复选框已勾选，则直接覆盖原文件。此时**必须先自动备份原文件为 `原文件名.bak`**（在同一目录），并在状态栏提示备份完成。
- 删除成功后，状态栏显示“删除完成，文件已保存至 ...”，并清空内部匹配缓存（提示用户可重新检索）。

### 2.6 状态与日志
- 关键操作期间状态栏实时更新（如“正在检索...”、“正在保存...”）。
- 错误情形使用 `messagebox.showerror` 显示，例如：未选择文件、检索词为空、文件中没有匹配句、编码错误、读写失败等。

## 3. 技术细节汇总
- 表达式解析函数封装为 `parse_query(query: str) -> callable`，返回一个接受句子并返回布尔值的函数。内部逻辑：按 ` OR ` 分割，再按 ` AND ` 分割，实现“或中的与”逻辑。
- 句子分割后保留索引，以高效重建删除后的文本。
- 所有 I/O 使用 `with` 和 `try...except`。
- GUI 使用 `pack` 布局，简单清晰。
- 若桌面路径不存在则回退，避免因系统特例导致崩溃。
- 代码开头添加 `# -*- coding: utf-8 -*-` 以支持中文注释。

## 4. 输出代码要求
- 只生成一个 `.py` 文件，包含完整实现和 `if __name__ == "__main__":` 入口。
- 只使用 Python 标准库。
- 代码有适当注释，解释关键逻辑。
- 避免使用任何可能因打包而失效的路径技巧（如依赖 `__file__` 定位资源等）。
